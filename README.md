# 叫料系統

分類式線上叫料商城，內建品項管理、叫料歷史紀錄、特殊設備採購申請與審核流程。
技術架構：**Node.js + Express + SQLite**（單一資料庫檔案，不需另外安裝資料庫伺服器）。

---

## 功能總覽

- **商城瀏覽**：分類 → 子分類 → 品項，每個品項可設定圖片、規格、顏色選項與數量
- **叫料下單**：填寫姓名/部門即可下單，送出即完成，不需審核
- **叫料歷史紀錄**：所有人皆可查詢，可用姓名/部門/日期區間篩選；管理後台可額外匯出 CSV
- **特殊設備採購**：目錄以外的設備可另外提出申請，**需要管理員審核**，送出後會 email 通知管理員
- **品項管理**：只有管理員（密碼登入）可以新增／編輯／刪除分類、子分類、品項
- **歷史紀錄不受品項刪除影響**：訂單會保存當時的品名/規格/顏色快照，就算之後品項被刪除或改名，過去的紀錄仍完整保留

## 環境需求

- Node.js 18 以上版本（建議使用 LTS 版本，目前用 v22 開發測試）
- 一台可以持續運行 Node.js 程式的伺服器或內部主機（Windows / Linux / macOS 皆可）

## 安裝與啟動

```bash
# 1. 進入專案資料夾
cd order-system

# 2. 安裝套件（會自動下載 better-sqlite3 對應你系統的預編譯版本）
npm install

# 3. 建立設定檔（複製範例檔後修改內容，見下方「設定檔說明」）
cp config.example.json config.json

# 4. 啟動伺服器
npm start
```

啟動後預設會在 `http://localhost:3000` 提供服務：

- `http://localhost:3000/index.html`　→　商城主頁面（一般使用者）
- `http://localhost:3000/admin.html`　→　管理後台（需要管理員密碼）

第一次啟動時，系統會自動建立 SQLite 資料庫檔案 `data/orders.db`，並放入幾筆示範分類/品項，方便你直接看到畫面長怎樣，之後可以在管理後台刪除或修改。

> 如果 `npm install` 時你們公司伺服器沒有對外網路，可以先在有網路的機器上執行 `npm install`，再把整個資料夾（含 `node_modules`）複製過去部署（`node_modules` 內含平台相關的編譯檔，複製時請確保來源機器的作業系統與目標伺服器一致，否則建議在目標伺服器本機執行安裝）。

## 設定檔說明（`config.json`）

複製 `config.example.json` 為 `config.json` 後修改：

```json
{
  "adminPassword": "請改成你自己的管理員密碼",
  "port": 3000,
  "smtp": {
    "enabled": false,
    "host": "smtp.your-company.com",
    "port": 587,
    "secure": false,
    "user": "smtp-帳號",
    "pass": "smtp-密碼",
    "from": "叫料系統 <no-reply@your-company.com>",
    "adminNotifyEmail": "admin@your-company.com"
  }
}
```

- `adminPassword`：管理員登入密碼，中英文、符號皆可（系統已處理編碼問題）
- `port`：伺服器監聽的埠號
- `smtp.enabled`：設為 `true` 才會真的寄送「特殊設備採購申請」的通知信；設為 `false` 時申請仍會正常送出並記錄，只是不會發信通知
- `smtp.host` / `port` / `secure` / `user` / `pass`：請填入公司的 SMTP 主機資訊（跟 Outlook、Gmail 商業版設定信箱時填的資訊相同）
- `smtp.adminNotifyEmail`：收通知信的管理員信箱，可以填多位管理員共用的信箱

修改設定後，需要重新啟動伺服器（`Ctrl+C` 後再 `npm start`）才會生效。

`config.json` 內含密碼等機密資訊，已加入 `.gitignore`，若使用版本控制請勿把它加進 git。

## 日常使用方式

### 一般使用者（商城）

1. 開啟 `index.html`，在右上角填寫姓名／部門（會記住在瀏覽器裡，下次不用重填）
2. 瀏覽分類、選擇規格/顏色/數量後按「加入購物車」
3. 點右上角購物車按鈕，確認品項後按「送出叫料單」
4. 可在「歷史紀錄」頁籤查詢自己或他人過去叫過的品項
5. 若要採購目錄以外的特殊設備，切到「特殊設備採購」頁籤填寫申請表單，送出後可在同頁查看審核狀態

### 管理員（後台 `admin.html`）

1. 輸入管理員密碼登入
2. **品項管理**：新增分類 → 新增子分類 → 新增品項（可設定圖片網址、規格/顏色選項、單位、排序、上下架）
3. **特殊採購審核**：查看待審核申請，核准或拒絕（可填寫審核意見）
4. **叫料歷史紀錄**：查詢所有人的叫料紀錄，也可以「匯出 CSV」下載 Excel 可開啟的紀錄檔

> 目前是單一管理員密碼共用的設計，所有能登入後台的人權限相同，沒有分層級的帳號系統。若未來需要分權限（例如各部門主管只能看自己部門），需要再另外開發帳號系統，目前先以最簡單的方式滿足「只有管理員能管理品項」的需求。

## 圖片說明

系統本身不支援上傳圖片檔案，品項圖片一律使用**網址連結**（例如公司圖庫、雲端硬碟的公開分享連結、圖床等）。在管理後台新增/編輯品項時，把圖片網址貼到「圖片網址」欄位即可。若留空，畫面會顯示一個含品名文字的預設灰底圖，方便之後補圖。

---

## 資料庫與備份

所有資料都存在 `data/orders.db` 這個單一檔案裡（SQLite）。

- **備份**：定期複製 `data/orders.db`（連同 `data/orders.db-wal`、`data/orders.db-shm`，如果存在的話）即可完整備份所有分類、品項、叫料紀錄、特殊採購申請
- **搬家/換伺服器**：直接把整個 `data/` 資料夾複製到新環境即可，不需要額外匯出匯入

## 部署到正式環境的建議

- 建議用 [pm2](https://pm2.keymetrics.io/) 或系統的 `systemd` 讓 Node 程式在背景持續運行、當機自動重啟，而不是直接開一個終端機視窗跑 `npm start`
- 若要用 HTTPS 或自訂網域，建議在前面加一層 Nginx / IIS 反向代理到這個 Node 服務的埠號（預設 3000）
- 內部工具通常不需要對外網際網路開放，建議只開放公司內網存取

## 部署到雲端（讓公司外面也能連）

如果只需要公司內網／WiFi 使用，前面的本機安裝方式就夠了，可以跳過這節。

如果需要讓大家在外面（手機行動數據、在家）也能連，建議部署到雲端主機（例如 Render、Railway 等平台），而不是把家用/公司電腦直接對外開放。系統已經支援用「環境變數」設定，不需要在雲端主機上編輯 `config.json` 檔案：

| 環境變數 | 對應設定 | 說明 |
|---|---|---|
| `ADMIN_PASSWORD` | 管理員密碼 | 務必設定，否則會使用不安全的預設密碼 |
| `PORT` | 監聽埠號 | 大部分雲端平台會自動注入，通常不用自己設 |
| `DB_DIR` | 資料庫存放路徑 | 設成雲端平台的「持久化硬碟／Disk」掛載路徑，資料才不會在重新部署時消失 |
| `SMTP_ENABLED` | 是否啟用 email 通知 | 設為 `true` 才會寄信 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` / `SMTP_ADMIN_NOTIFY_EMAIL` | SMTP 相關設定 | 對應 `config.example.json` 裡 `smtp` 底下的欄位 |

環境變數的優先順序高於 `config.json`，兩者也可以混用（例如本機保留 `config.json` 方便本機測試，雲端平台改用環境變數）。

**重要**：`DB_DIR` 這個設定很關鍵。像 Render 這類平台，如果沒有掛載「持久化硬碟」，容器重新部署或重啟時本機檔案會被清空，叫料歷史紀錄就會不見。部署時請務必在平台上新增一個 Disk／Volume，掛載到某個路徑（例如 `/data`），並把 `DB_DIR` 設成同一個路徑。

## 已知限制 / 之後可以擴充的方向

- 管理員是單一共用密碼，沒有個別帳號與操作紀錄（誰改了什麼品項）
- 圖片僅支援網址連結，不支援直接上傳檔案
- 沒有內建的圖形化報表（目前用 CSV 匯出後可在 Excel 自行製作報表/樞紐分析）
- 目前叫料下單不需審核；如果之後也想加審核流程，可以參考特殊採購申請的審核機制來擴充
